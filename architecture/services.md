# Сервисы и зоны ответственности

Стек снят с текущих `pom.xml`. Если задача меняет зависимость — сначала обновить этот файл.

Общее: **Java 21**, **Spring Boot 4.1.1**, **Lombok**.

---

## REST-CORE

**Роль:** публичный фасад contactApi. Оркестратор. Единственный, кто отдаёт клиентский JSON.

**Владельцы:** Дмитрий (middle), Андрей, Влад. Архитектура — Дмитрий @Mipowka.

**Стек в репо:** `webmvc`, `validation`, `data-jpa`, PostgreSQL, OpenFeign, springdoc OpenAPI.

**Делает**

- HTTP API поиска контактов;
- валидация входа;
- вызов `ai-core` по внутреннему контракту;
- PostgreSQL: кэш/история/сущности (схема уточняется задачами на rest-core);
- единый error-format для клиентов;
- OpenAPI для внешних интеграций.

**Не делает**

- prompt / вызов LLM / работу с ProxyAI;
- Telegram-логику.

**Интеграции исходящие:** `ai-core` (Feign), PostgreSQL.

---

## AI-CORE

**Роль:** интеллектуальный NLP-парсинг названия и извлечение контактов через LLM.

**Владельцы:** Дмитрий @Dimas5696 (senior), Андрей.

**Стек в репо:** `webmvc`, `spring-ai-starter-model-openai` (OpenAI-compatible → ProxyAI).

**Делает**

- внутренний API для `rest-core`;
- нормализация названия (опечатки, регистр, разговорные сокращения);
- prompt + structured output;
- клиент **ProxyAI**;
- маппинг ответа модели во внутренний DTO;
- таймауты, ретраи, деградация, если ProxyAI недоступен.

**Не делает**

- публичный API;
- Telegram;
- JPA/PostgreSQL (в текущем pom БД нет — так и оставляем).

**Интеграции исходящие:** только ProxyAI API.

---

## TG-BOT

**Роль:** клиентский канал. Принимает название организации в Telegram, ходит в `rest-core`, показывает адрес и телефоны.

**Владельцы:** Дмитрий @Dimas5696 (senior), Олег.

**Стек в репо:** `webmvc`, OpenFeign, springdoc. Telegram-библиотеки ещё нет — это отдельная задача.

**Делает**

- диалог/команды бота;
- Feign/WebClient на публичный (или внутренний) API `rest-core`;
- человекочитаемый ответ из JSON.

**Не делает**

- вызов `ai-core` или ProxyAI;
- запись в PostgreSQL rest-core.

---

## ProxyAI (внешний)

**Роль:** один HTTP-прокси к нейросетям. Не наш git-модуль.

**Кто вызывает:** только `ai-core`.

**Как стыкуется с кодом:** в `ai-core` уже есть Spring AI OpenAI starter — ProxyAI должен быть OpenAI-compatible (`base-url` + `api-key`).

**Делает команда:** ключи и URL — DevOps (Максим) через env. Код клиента и промпты — ai-core.

**Не светить:** токены, ключи, внутренний URL в задачах для tg-bot/rest-core клиентов.

---

## ANY OTHER WEB / MOBILE

Внешние потребители. Наш контур их не разрабатывает. Для них `rest-core` обязан иметь стабильный контракт и OpenAPI.
